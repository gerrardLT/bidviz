## 四、P2 —— 质量 / 维护性 / 性能（按主题归并）

**并发与 IO**
- `/api/doc`（fullimage 模式）写热点：`ensure_page` 无条件重写整本 pages ledger（`bidviz_fullimage_store.py:331`）+ 每页重复全项目解析（`_section_blocks` 每页全量 load）→ 一次 `/api/doc` = 数百次文件锁 + 数十次全量 JSON 重写；而它在每个任务完成后必被前端调用。
- 汇编读图与 publish 跨锁竞争：`do_rebuild` 不持 `_ledger_lock` 逐页读 published PNG，与请求线程的 `os.replace` 发布并发 → Windows 共享冲突或新旧版本混入（窗口秒级，概率低）。
- legacy regen 无页锁、最终图非原子直写（server.py:445-482、`bidviz.py:520`）——切回 legacy 即暴露。
- `supersede_records` 多文件非事务（`bidviz_memory.py:1549-1566`），中断留冲突且 `validate_memory` 不自愈冲突。
- `RunRecorder.record` 每条事件全量重读 events.jsonl（O(n²)）；每次 `POST /api/section` 新建 run 目录，`work/runs/` 无限增长。

**安全硬化（均非漏洞级，纵深防御项）**
- GET 端点零防护且有磁盘写副作用：`/api/doc` 在 legacy/html 模式会落盘重规划（server.py:387-388）、memory GET 重建索引——恶意网页 `no-cors` fetch 即可跨站触发写。
- POST body 无大小上限、`rfile.read(n)` 无 socket timeout（server.py:874-878）→ 残缺客户端可挂起线程。
- 500 回显 `str(exc)` 可含绝对路径（server.py:1173-1175）；`do_GET` 无异常兜底（do_POST 有）。
- `/api/pdf?draft=0` 判真 bug：`bool(parse_qs(...).get("draft"))` 对 list 恒真（server.py:953）。
- 静态服务 Windows 盘符相对路径边角（`C:foo`），影响极低。

**死代码（合计约 1500+ 行）**
- 整模块死：`build_sample_s003.py`（零引用，且内含 `page_plan_from_dict` 过时拷贝误导）。
