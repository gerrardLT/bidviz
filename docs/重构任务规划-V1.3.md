| D11 | 拒收降级 | 文字门禁重试 3 次仍失败 → **拒收转人工**：S3 门控暂停生图队列，展示 diff 明细，人在 Web 改任务单后继续 |
| D12 | KPI 数量 | **按类浮动**：A/B 类 ≤3 条；C/E/H 类 1–2 条；D/F/G 类 0 条（全表格，不出 KPI 卡）；优先级 工期>工程量>关键型号 |
| D13 | 生图预算 | **估算+告警**：token-cost 实测价估算全册预算，超 20% 在 run 内告警（不阻断）；硬上限待用户给定金额后启用 |

补充定性（评估结论，作为本规划的公理）：
- 新体系＝设计层，旧体系＝工程层；重构＝**设计换新 + 工程留旧**。
- 统一骨架：**决策 / 执行 / 验证 三层分离**——设计判断前移到 plan 阶段并冻结；执行是确定性渲染（只吃 tokens + json + 槽位）；质量是可测门禁。
- 分工铁律（V1.2 修订）：**AI 可写标注级文字，但每个字必须被校验**；页面级文字仍矢量。图像模型承担场景/结构/工艺/空间关系画面＋图内标注；流程/组织/时序/参数图表仍矢量图型。
- 文字准确性公理（V1.2）：图内文字＝`text_spec` 期望串；生图后 VLM 回读逐条 diff；隐藏矢量检索层使纯视觉页仍可 Ctrl+F 与反抽审计。`GOAL.md` 不变量第 3 条被 D9/D10 取代（归档时注明）。
- 审计统一口径：**页上文字 ⊆ 原文且可定位**（整段=逐字在 PDF；提炼行=原文前缀在 PDF）。

## 1. 目标架构

### 1.1 决策层（plan-time，落盘可审改，冻结带 version）

### 1.3 验证层（门禁）

| 门禁 | 实现 | 阻断 |
|---|---|---|
| 乱度逐页 | `src/audit_layout.py`（新）：填充色块数/色种数/左边界离散度，阈值按样图风标定 | 超标页 → DRAFT + 报告 |
| 内容审计 | 现有 `audit_coverage`（口径统一为"页上文字 ⊆ 原文且可定位"） | 缺失 → 阻断 |
| 视觉回归 | 组件固定数据渲染 → 基线 PNG → 像素 diff（Pillow） | 超阈值 → 测试失败 |
| 生图尺寸 | 实际像素 vs 请求档 | 降级 → 重试/换档/降版面用途 |
| 文字准确性 | VLM 回读图内文字 vs `text_spec` 期望串 diff（归一化匹配，见 4.5b） | 乱码/错字/缺字/多字/污染 → 重试 3 次 → 拒收转人工（D11，S3 队列暂停）；签认点抽审 5 张 |
| 隐藏检索层 | 隐藏层文本反抽 vs 原文（audit_coverage 经隐藏层） | 缺失 → 阻断 |
| issues | open 状态存在 | 阻断 final 或 DRAFT 水印+附录页；waive 必须留痕 |
| 分类抽检 | 每章抽 2 节人工核对主类 | 一致率低于阈值 → 回炉 |

### 阶段 4 · 生图侧改造（3–4 天，含生图等待）

- 4.2 figure-plan 任务单字段 + subject 白名单过滤（flow/org/timeline/param 拒收转矢量）。

- **验收**：58 节图位文字准确性通过率 100%（重试后）、尺寸达标率 100%、同对象跨节外形一致（人工抽 5 组）、隐藏层反抽审计 100%。

## 7. V1.1 增补 · Web 驱动的阶段门控编排（run orchestrator）

### 7.1 运行模型

- `bidviz run <project>` 创建一次 run：状态与产物落 `work/runs/<run_id>/`（`state.json` + `artifacts/`）；启动即 `webbrowser.open(http://localhost:<port>/?run=<id>)`，端口冲突自动 +1。
- **流式**：SSE 端点 `/api/run/<id>/stream`（text/event-stream）。子进程步骤以行缓冲 stdout 转发为 `log/line`，结构化事件：`stage/start`、`progress{n,total}`、`artifact{kind,path}`、`gate/wait{stage,preview[]}`、`stage/done{summary}`、`run/finished`。
- **门控**：`gate/wait` 时 run 暂停；Web 展示该阶段结果预览；用户点确认 → POST `/api/run/<id>/confirm`（带 stage + 底层 json 快照 hash，hash 不符即拒绝并提示重新预览）；驳回需填意见，留痕进 run 日志。
- **微调**：各决策件走 PATCH API（`layout-classification` / `page-plan` / `figure-plan` / `issues` / `tokens` / `edits`）；tokens 修改强制回到签认点①。
- **断点续跑**：`state.json` 记录阶段与冻结件 version；中断后 `bidviz resume` 或 Web「继续」；已冻结且 version 未变的件不重算。
- **CLI 定位**：`ingest/plan/generate/build/audit` 保留为调试入口（函数级被 run 复用）；headless 模式只允许复用已冻结签认件，缺签认即失败退出。

## 8. V1.1 增补 · 用户流程与人工触点

### 8.1 冷启动（新文档）

1. `bidviz init x` → 文档入 `inputs/` → 编辑 `bidviz.toml`。
2. `bidviz run x` → **Web 自动打开** → S0…S5 逐站流式+预览+确认。
3. 交付包五件套：正式 PDF、可编辑排版源、图表素材与来源清单、原文对应及改动记录、问题与验收报告。

### 8.2 日常迭代小回路（不重跑全链）

- 改一句正文：Web 编辑 → `edits.json` → 仅 S4–S5 重跑（不碰图）。
- 换一张图：Web 改任务单 → S3 单节重跑 → S4–S5。
- 调版式：改 `page-plan` 槽位 → S4–S5；组件像素 diff 超阈值告警。
- 换文档：S0–S2 重跑（半自动+抽检），其余复用。

### 8.3 人工触点（全系统 5 处，其余确定性）

| 触点 | 审什么 | 频率 |
|---|---|---|
| ① 分类矩阵（S1 门控） | 主辅类与内容块拆分 | 每项目 1 次 + 换文档 |
| ② issues 决断（S2 门控） | 缺单位/口径冲突/歧义：确认或豁免留痕 | 按需，阻断 final |
| ③ 风格种子（S3 门控） | 每类题材 1 张图风格 | 每项目 1 次 |
| ④ golden page / 模板批（S4 门控） | 版式观感 | 阶段 2/3 各 1 批 |
| ⑤ final 签发（S5 门控） | 三道验收关 + 未决清单 | 交付前 1 次 |

与旧流程的本质差异：人工从「逐页调版式、逐图碰运气、全文覆盖焦虑」的无门禁暗处，**全部前移到 5 个签认站**；签认之后 58 节 × ≤3 页为机器确定性产出。
