# 局部改字操作手册（全图路线）

> 适用：`projects/anke-35kv` 这类 `[layout].engine = "fullimage"` 的项目。
> 目标：在网页上对已生成的 2K 全图做小范围文字修正，不动版式、不动框外像素。
> 当前门禁：**纯人工审核**；OCR 乱码检测是待办，不阻塞本流程。

## 1. 一次性回填（已执行，2026-10-21）


- 把 `work/fullimage/Sxxx_pN.png` 复制为 `candidates/<sid>/pN/v0001.png`，并发布到 `published/`；
- 初次回填会备份 `work/fullimage-pages.json`；深度清理后历史备份已由 cleanup manifest 取代；
- 幂等：已有候选/已发布的页面会跳过；
- 正常结果：`imported=103, skipped=0, missing=[], published=103, can_build_final=true`。

只回填某几节：`--section S030,S031`。

## 2. 启动网页

```powershell
.\.venv\Scripts\python.exe web/server.py 8771 projects/anke-35kv
```

打开 `http://127.0.0.1:8771/`。左侧导航选节，右侧每页有「当前已发布 / 最新候选」两栏。

看图与找字：

- 点任意页图打开**全屏查看器**；滚轮缩放，拖动平移，顶部有「适应 / 100% / 200% / 400%」；
- 顶部「大图审阅」会把右侧字段隐藏、已发布/候选改为单栏，每张图占满工作区，适合先整体找问题；
- 找到要改的字后，从对应栏点「局部改字」，直接进入全屏编辑器。

## 3. 改字步骤

1. 在要改的那一栏（已发布或最新候选）点「局部改字」；编辑器默认 **100% 原像素**，文字按 1:1 显示；
2. 先点「适应」看整页定位，再点「100% / 200% / 400%」放大；滚轮缩放、空格或中键拖动平移；
3. 在图上拖框，**紧贴要改的文字**；框会自动外扩 6px 作为遮罩余量；
4. 框选后可以精调：拖框内整体移动，拖 8 个边/角手柄改大小，方向键 1px、Shift+方向键 10px，或在右栏直接输入 x0/y0/x1/y1；
5. 鼠标移动时有 5× 放大镜，右栏有框内预览；确认框覆盖整个旧字符、且给新字留够宽度；
6. 在右栏输入替换文字（最多 200 字），点「提交局部改字」，等待约 **24–46 秒**（¥0.08/次）；
7. 完成后右栏出现新候选 `vNNNN`，页面状态列会出现「待审 vNNNN」标记；
8. 重新打开大图，放大检查框内文字、字体、字号、基线；
9. 满意 → 「批准并发布」；不满意 → 「退回」，再重新框选提交。

发布后左栏“当前已发布”更新；系统只保留最近一层 future rollback。2026-10-22 深度清理前的历史回滚二进制已裁剪，旧版本元数据仍在事件/manifest 中，但不能恢复其像素文件。

## 4. 门禁与记录

局部改字候选会写以下自动检查（无 OCR）：

| 检查 | 说明 |
|---|---|
| dimensions | 输出必须与源图同尺寸（2048×2896） |
| min-width | 宽度 ≥ 2048 |
| portrait / aspect-ratio | A3 竖版 |
| outside-unchanged | 框外（外扩 12px 以外）像素零变化；正常合成下是结构不变量 |
| inside-change | 框内必须真的发生变化：零变化直接 **block**，变化过少 **warn** |
| edit-box | 框坐标合法、面积足够 |
| manual-review | **warn**：OCR 门禁待办，必须人工放大复核 |

候选元数据 `edit` 字段记录：基准版本、框坐标、替换文字、裁剪窗、补丁坐标、是否做了色彩对齐、返回尺寸、耗时、请求/返回哈希。审核面板会显示「✎ 局部改字 published v0001 → v0002 · 框 [...] · “挖”」。

## 5. 框选规范

- 优先在 100% 以上放大后再框，避免在缩小视图里把相邻字一起框进去；
- 框要覆盖**整个旧字符/词组**，不要只框一半；框四周留 1–2px 余量，不要压住相邻字；
- 不要跨越大面积照片或复杂纹理；优先改表格、标题条、正文等平坦背景；
- 单字改字建议框 30×50 像素左右（原图 2048×2896 坐标）；
- 替换文字长度要与框的宽度匹配；字太多会挤在一起，建议换更大的框；
- 一次只改一处；多处修改分别提交，每次都生成独立候选，便于回滚。

## 6. 失败与重试

| 现象 | 处理 |
|---|---|
| 提交后 job `failed`，提示“返回空白” | 模型没写出内容；重新提交，或把框放大 10–20% |
| 字太大/太小、基线偏移 | 退回后重新框选；新版按模型原始坐标贴回，若仍偏移，检查框是否把旧字框偏 |
| 框内有明显矩形接缝 | 新版已对补丁边缘羽化并对齐模型背景色；仍有接缝时退回重试，或把框稍微偏移，让模型重新取背景 |
| 门禁提示“框内像素未变化” | 模型没有改写内容；放大确认后重新框选/重试，不要直接批准 |
| 一次要改很多字/多处 | 用「生成候选 2K」整页重画，不要连续局部改 |
| 接口 400/404 | 检查供应商 edits 接口与凭据；job 的 `error` 会保留原因 |

待审候选保留在 `candidates/`，不会覆盖已发布图；已决历史候选可按 retention policy 裁剪为仅留元数据与事件证据。

## 8. 已知边界

- 本轮**不做 OCR 自动检测**：RapidOCR/原文比对列入 `docs/PROGRESS.md` §3 待办；
- 不做同页字形移植/矢量补丁（B2）；AI 改字效果不满意时先重试，后续可加；
- 接口整页重绘的特性决定了必须“裁剪 + 只合成遮罩”，不要拿返回图整页替换；
- 合成已改为“补丁按模型原始坐标贴回 + 补丁边缘羽化 + 模型背景色对齐”；补丁不再重新居中；
- 浅色平坦背景上模型补丁通常覆盖整个遮罩，接缝风险最高；深色背景上补丁可能只含字形，背景保持原图；
- 局部改字不改变隐藏检索层；改字后 PDF 的 Ctrl+F 仍按原文检索。
