# 局部改字操作手册（全图路线）

> 适用：`projects/anke-35kv` 这类 `[layout].engine = "fullimage"` 的项目。
> 目标：在网页上对已生成的 2K 全图做小范围文字修正，不动版式、不动框外像素。
> 当前门禁：**纯人工审核**；OCR 乱码检测是待办，不阻塞本流程。

只回填某几节：`--section S030,S031`。

## 2. 启动网页

```powershell
.\.venv\Scripts\python.exe web/server.py 8771 projects/anke-35kv
```

打开 `http://127.0.0.1:8771/`。左侧导航选节，右侧每页有「当前已发布 / 最新候选」两栏。

## 3. 改字步骤

1. 在要改的那一栏（已发布或最新候选）点「局部改字」；
2. 在图上拖框，**紧贴要改的文字**（框会自动外扩 6px 做羽化）；
3. 在下方输入替换文字（最多 200 字）；
4. 点「提交局部改字」，等待约 **24–46 秒**（¥0.08/次）；
5. 完成后右栏出现新候选 `vNNNN`，页面顶部状态变为「候选待审」；
6. 点图片可全屏放大；检查框内文字、字体、字号、基线；
7. 满意 → 「批准并发布」；不满意 → 「退回」，再重新框选提交。

发布后左栏“当前已发布”更新；需要撤销时点「回滚」，恢复上一版发布。

## 4. 门禁与记录

局部改字候选会写以下自动检查（无 OCR）：

| 检查 | 说明 |
|---|---|
| dimensions | 输出必须与源图同尺寸（2048×2896） |
| min-width | 宽度 ≥ 2048 |
| portrait / aspect-ratio | A3 竖版 |
| outside-unchanged | 框外（外扩 12px 以外）像素零变化 |
| edit-box | 框坐标合法、面积足够 |
| manual-review | **warn**：OCR 门禁待办，必须人工放大复核 |

候选元数据 `edit` 字段记录：基准版本、框坐标、替换文字、裁剪窗、返回尺寸、耗时、请求/返回哈希。审核面板会显示「✎ 局部改字 v0001 → v0002 · 框 [...] · “挖”」。

## 5. 框选规范

- 框要覆盖**整个旧字符/词组**，不要只框一半；
- 不要跨越大面积照片或复杂纹理；优先改表格、标题条、正文等平坦背景；
- 单字改字建议框 30×50 像素左右（原图 2048×2896 坐标）；
- 替换文字长度要与框的宽度匹配；字太多会挤在一起，建议换更大的框；
- 一次只改一处；多处修改分别提交，每次都生成独立候选，便于回滚。

## 6. 失败与重试

| 现象 | 处理 |
|---|---|
| 提交后 job `failed`，提示“返回空白” | 模型没写出内容；重新提交，或把框放大 10–20% |
| 字太大/太小、基线偏移 | 退回后重新框选，框尽量贴住原字符 |
| 框内有明显矩形接缝 | 退回后重试；或把框稍微偏移，让模型重新取背景 |
| 一次要改很多字/多处 | 用「生成候选 2K」整页重画，不要连续局部改 |
| 接口 400/404 | 检查供应商 edits 接口与凭据；job 的 `error` 会保留原因 |

所有失败候选保留在 `candidates/`，不会覆盖已发布图。

## 7. 命令行（离线/验收）

```powershell
# 基于已发布版本改字（不写入候选库，输出到 work/fullimage/_localedit.png）
.\.venv\Scripts\python.exe -m src.bidviz_local_edit edit --root projects/anke-35kv `
  --sid S030 --page 1 --box 944,815,974,870 --text 挖
```

基于指定候选：`--base-version 1`；指定输出：`--out <path>`。

## 8. 已知边界

- 本轮**不做 OCR 自动检测**：RapidOCR/原文比对列入 `docs/PROGRESS.md` §3 待办；
- 不做同页字形移植/矢量补丁（B2）；AI 改字效果不满意时先重试，后续可加；
- 接口整页重绘的特性决定了必须“裁剪 + 只合成遮罩”，不要拿返回图整页替换；
- 局部改字不改变隐藏检索层；改字后 PDF 的 Ctrl+F 仍按原文检索。
